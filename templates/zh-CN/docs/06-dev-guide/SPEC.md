# SPEC

## 用途

定义开发过程中的硬约束、质量底线和工程规范。

## 建议章节

### 1. 开发红线

- 不允许的捷径
- 不允许绕过的校验或审计

### 1.1 AI 修改禁区

用于标记 AI 不应自动修改的代码、配置或文档片段。常见场景包括：迁移脚本、生产配置、安全策略、协议兼容层、客户定制逻辑、手写生成物边界。

推荐标记格式：

```text
// docs: frozen <原因>
# docs: frozen <原因>
<!-- docs: frozen <原因> -->
```

AI 处理带有 `docs: frozen` 标记的区域时应遵守：

- 不自动编辑该区域，除非用户明确要求或对应 Current 权威文档已更新
- 如任务必须触碰该区域，先说明风险、影响范围、回退方式和验证方法
- 如只是相邻代码改动，保持标记和区域内容不变
- 完成后在收口说明中注明是否触碰冻结区

### 2. 错误处理

- 错误分类
- 返回策略
- 可恢复与不可恢复边界

### 3. 可观测性

- 日志
- 指标
- 追踪
