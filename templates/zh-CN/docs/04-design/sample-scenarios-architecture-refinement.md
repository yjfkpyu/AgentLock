# 样板场景细化与模块边界设计

## 用途

当项目较复杂、仅靠高层架构不足以冻结实现边界时，可用本文档承接少量代表性样板场景的正式细化。

本文档是可选正式文档。

适用条件：

- 项目存在多个高价值或高风险场景
- 这些场景已经成为模块边界、对象流、状态机或接口契约设计的主要输入
- 如果不单独冻结样板场景，正式设计会长期停留在抽象口径，难以指导实现

## 建议章节

### 1. 样板场景选择原则

- 为什么选择这些场景作为样板
- 它们分别覆盖了哪些核心机制

### 2. 场景级模块边界

- 每个样板场景涉及哪些模块
- 各模块在场景中的职责分工

### 3. 对象流与状态流

- 场景中的关键对象如何流转
- 状态如何推进、挂起、恢复、升级或结束

### 4. 控制面与运行态边界

- 若项目存在控制面 / 运行态分离，写清职责边界
- 若项目不存在该分层，可改写为调度层 / 执行层、主机 / 从机、上位机 / 设备侧或应用层 / 驱动层边界
- 哪些节点需要人工介入

### 5. 交互对象与接口影响

- 哪些读模型、命令模型或事件模型需要由样板场景反推出来
- 场景细化对 API、数据模型或能力绑定有什么影响

## 不应写入本层的内容

- 大量开放式讨论过程
- 还未稳定的候选方案对比
- 字段级契约的最终定义

这些内容应分别放在 discussions、proposed-design 或对应正式专题文档中。
