# Runtime / Control-Plane 设计规范

## 用途

定义控制面与运行态的职责边界、状态机、恢复策略和审批边界。

如果项目不存在显式控制面 / 运行态分离，可将本文缩减为“执行状态机 / 运行时状态设计”，或不单独启用。

## 建议章节

### 1. 控制面职责

- 任务接入
- 编排决策
- 审批调度
- 状态管理

### 2. 运行态职责

- 实际执行
- 工具调用
- 中间状态回报

### 3. 状态机

- 主状态
- 子状态
- 挂起、恢复、失败、补偿规则

### 4. 人工介入边界

- 哪些状态需要人工确认
- 哪些失败可以自动恢复

## 不应写入本层的内容

- 高层愿景、战略定位（属于 01-vision）
- 需求描述和用例定义（属于 02-requirements）
- 系统级架构边界（属于 03-architecture）
- 项目管控信息（属于 05-project）
- 开发规范和编码标准（属于 06-dev-guide）
