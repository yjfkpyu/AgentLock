# 核心功能登记册

> 本文档应作为项目功能范围、实现状态、关联文档、关联代码和验证证据的唯一权威清单。

## 当前阶段与 Track

建议每个功能或能力都标注 `Track`，用于避免当前阶段范围与远期设想混在一起。`Track` 的唯一权威定义见 [../08-process/conventions.md](../08-process/conventions.md) §2。

如果项目很小，可以省略 `Track` 列；但一旦出现“先做最小版本、后续再演进”的情况，建议启用。

## 文档与代码同步规则

- 权威文档应指向 Current 状态的 PRD、架构、API、数据模型或专题设计文档
- 相关代码入口可以是模块目录、关键类、路由、接口、迁移脚本或配置文件
- 最后验证应写命令、测试、人工检查或“未验证”，不要留空
- 如果功能文档与代码现实不一致，在 [../../SESSION.md](../../SESSION.md) 的 Known Drift / Open Questions 中登记

## 维护规则

- AGENTS.md 和 docs/README.md 中涉及功能范围的描述，应与本文档一致
- 统计摘要应在功能条目变更后同步更新
- 不要把完整功能清单拆散到其他文档重复维护
- 功能 ID 应与计划文档、SESSION 当前工作项、代码入口保持可追溯关联
- 当功能跨阶段推迟时，应同时更新阶段标记和状态标记
- 当功能从 NOW 改为 LATER，或从 LATER 改为 NOW / BOTH 时，应同步检查 [evolution-backlog.md](evolution-backlog.md)
