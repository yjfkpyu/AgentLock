# 系统总体架构

## 用途

描述系统的顶层分层、模块边界、主要交互路径和扩展方式。

> 分层应由项目实际形态决定，不要默认每个项目都存在前端、后端、控制面和运行面四段式结构。

## 建议章节

### 1. 总体分层

- 可按项目实际选用，例如：
	- 交互 / 接入层（UI、CLI、API、消息入口、设备接口）
	- 应用 / 编排 / 控制层
	- 领域 / 引擎 / 执行层
	- 平台 / 集成 / 数据 / 硬件层
- 对嵌入式或单机程序，也可以只保留更少层级，但必须写清职责边界

### 2. 关键模块

- 每个模块的职责
- 模块之间允许和禁止的交互

### 3. 核心数据流

- 从输入到输出的主要路径
- 关键校验点和决策点

### 4. 扩展策略

- 如何新增模块、能力、子系统或插件
